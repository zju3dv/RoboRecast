You own one prepared DROID episode from initial observation to a passing physical rollout. Work in the current output directory. The task JSON gives absolute paths to the episode, repository, Python interpreter, mode and any source reconstruction. The repository's five skills are under `.agents/skills`. Use the public Python tools in `src/roborecast` and the Blender harness in `third_party/agenticSTAR`.

1. **Read the demonstration.** Inspect short clips or selected frames from `derived/videos`. Use `derived/actions_canonical.npz` and capture timestamps for timing. Identify relevant objects, support, contacts, state changes and their order. In reconstruction mode author `intent.json` using the requirements schema in `examples/microwave`. Infer object identity and the goal from the visual evidence. Ignore source language labels. Freeze the interaction order and tolerances before tuning. In augmentation mode read the accepted source bundle and the requested recipe.
2. **Initialize the scene.** Use the provided complete robot in `robot/`. Preserve its kinematics, gripper and base calibration. Model relevant objects and support in Blender with the AgentSTAR harness. Up to three independent modeling workers may run together when available. Use one external camera's initial view, metric ZED depth and LingBot-Depth refinement. Run this pipeline's `observe.py EPISODE --frames 0 --out observations/ext1` to prepare a matching RGB, depth and intrinsics tuple for the depth adapter. For articulated units also use a few operation keyframes. Keep AgentSTAR materials. Estimate material then physical priors. Build per-link CuACD collision pieces for complex shapes. Check support, joint travel and task-relevant clearance. Align the overall layout and contact surfaces. In augmentation mode reuse accepted units and replace the requested robot, objects and placements. Keep passive objects free and the support fixed.
3. **Bind the motion.** Assemble `bundle/scene.xml` and `bundle/runtime.json`. Rebase mesh file paths when moving a scene. Extend the robot's `settled_initial` key with each new joint's initial state. Author `bundle/program.json` using the microwave program schema. Waypoints carry time in seconds, flange pose in metres and xyzw, gripper opening in metres, motion mode and incoming interaction IDs. Align grasp and release to their respective target objects. Preserve demonstrated operation timing. For reconstruction, define numerical checks in `bundle/success.json`, including containment for insertion or bounded joint travel for articulation. For reconstruction, write `bundle/observables.json` with `passive_roots` (MuJoCo names of the manipulated root bodies) and `tail_speeds` (keys such as `physical:fruit_tail_speed` mapped to measured MuJoCo body names).
4. **Preserve the contract.** For reconstruction copy the frozen intent to `bundle/requirements.json`. For augmentation write `bindings.json`: `entities` maps exact source role names, body names or geom patterns to target names; `anchors` maps predicate locations such as `G/0` or `transport/1` to the source body anchoring a world position tolerance. Leave displacements, contact times and physical thresholds intact. Run `binding.py SOURCE/bundle bundle bindings.json intent.json --initialize-physics` from this pipeline with the task interpreter, then copy the result to `bundle/requirements.json`. Initialize physics once after resolving the bindings. Keep mapped required checks and passive observables across repairs. Add target-specific diagnostics if useful.
5. **Execute and diagnose.** Run this pipeline's `rollout.py bundle --out rounds/01 --save-prefixes`. Read the motion, physical and interaction results. Diagnose the earliest failure and change the responsible variable. Use a fresh round directory and `--resume rounds/01` for compatible prefixes. Compare sparse rendered frames to the source using `python -m roborecast.keyframe --help`. Repeat in this same session until success or the task budget. Never animate passive objects through states, weld a grasp, or relax a source threshold to pass.
6. **Review.** Inspect an actual source frame and a rendered frame from the passing candidate. Write `visual-review.json` with paths `source_frame`, `rollout_frame`, a concrete `observations` summary of appearance, contact and outcome, and `decision`. For recipes with `layout_check`, run this pipeline's `layout.py SOURCE/bundle bundle RECIPE bindings.json` before finishing (write the recipe from task.json into a local JSON file). Its bounds apply to actual scene geometry. If the source uses different observable names, record `layout-roles.json` with `source` and `target` objects, each naming its `payload` and `receptacle` bodies. Pass it with `--roles`. Repair a failed layout and repeat the rollout. Finish with the successful candidate in `bundle/`. Before exiting, use the task interpreter to run `<repository>/pipelines/droid/run.py verify .`. It checks the contract, review and layout, then replays the final candidate without checkpoints. If it fails, inspect its error or report, repair the candidate in this session and repeat. After a scene or program edit, render and review the updated evidence. Finish only when verification writes `accepted.json` or the budget expires.
