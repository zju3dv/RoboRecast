# v2.2 operation evidence and placement

Before modeling manipulated objects, inspect a few clear full frames and contact frames with `inspect_operation_reference`. Batch samples: `{"samples":[{"row":224,"camera":"right_wrist"}]}`. After viewing the returned full frame, crop with `{"samples":[{"row":224,"camera":"right_wrist","box_xyxy_normalized":[0.3,0.4,0.72,0.85]}]}`. Boxes refer to the original single frame, never a contact-sheet tile. Optional padding defaults to 0.12 per side. Output includes original resolution, actual pixel crop, boxed context and same-row left/right FK. Full video proxy frame index equals canonical row. Do not invent boxes before viewing the frame. Prefer unobstructed shape frames plus contact frames, not many redundant images.

FK uses measured source joint positions and the input route prior. Its world frame is the source route frame, not automatically your reconstructed scene frame. Read route provenance; velocities have already been integrated upstream. Gripper values in the canonical input are normalized openings in [0,1], not calibrated metric finger separation. Camera pixels and approximate virtual extrinsics do not provide metric object coordinates.

`suggest_object_placement` accepts `row`, `side`, `local_contact_point_m`, and 1..4 `object_quaternions_wxyz`. It subtracts the rotated object-local contact offset from the source pinch position. Optional `support_height_m` and `local_support_point_m` project the candidate onto a horizontal support and report the resulting contact residual. Orientation and geometry are your estimates; a single contact cannot determine them. Nonzero residual identifies conflicting assumptions. Candidates are advisory, not registered, settled or collision-certified. Align the source world to your scene consistently before using them; do not treat hand pose as object center.

Preserve operation-critical shape: continuous openings, realistic wall/handle thickness and grasp access. Record a short `reference_grasp` description and evidence rows in `workspace/modeling_notes.json`: contact region, approach, jaw placement and allowed object tilt. Background layout may remain approximate. Compare a focused `render_mobile_scene_preview` using `focus_body`, `reference_crop_path`, and up to 8 `detail_geoms`. Geometry sizes use MuJoCo conventions (box half extents). The crop and preview are for qualitative shape review, not pixel alignment. Visual meshes may be smooth while collision uses compact convex pieces preserving the same contact surface and cavity; do not use one convex hull that fills an opening.

During rollout, default to action repairs: grasp position/orientation/opening timing, then lift/clearance, hold posture, path and speed. Keep successful prefixes. Revise geometry only for named visual/geometric evidence, not to accommodate a failed pose by adding arbitrary lips, supports or thickness. Do not change geometry and action together in one diagnostic experiment unless their dependency is explicit. Mass/friction must remain plausible. If many source postures fail, check robot frames and placement assumptions.

Probe the grasp AND a short authored lift/clearance phase before expanding carry. Use the existing `probe_mobile_stage` through that lift phase (compile through it first); there is no hidden auto-lift. Per-hand slip/contact evidence and top collision pairs now come back directly. A stationary grasp PASS alone does not establish transport stability. Read the local sheet first, expand full diagnostics only for missing evidence.

Record a compact `operation_relations` list in the same modeling notes: subject/support or obstacle names, source evidence rows, observed support/overhang, grasp access and required clearance, plus uncertainty where visibility is insufficient. Describe qualitative relations, not invented precise source coordinates. Approximate layout must preserve the conditions that determine how the operation is performed. Preserve source-supported overhang or openings when present; do not invent them to make access easier. Compare the initial/precontact relation in the existing focused preview against source context, not only an isolated object crop.

Action-first repair also covers support boundaries, obstacles and registered object poses: shrinking/moving a support or repositioning an object can change grasp difficulty even when object shape stays fixed. Such a change needs named source/geometric evidence and a brief explanation in the modeling notes; a failed grasp alone is not that evidence. If a source-consistent setup remains infeasible, report the specific conflict rather than simplifying away the necessary contact/obstacle relation. Independent review checks these relations in the existing review pass.
